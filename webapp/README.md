# BBB MP4 — панель конвертации (dashboard)

Отдельный веб-сервис для развёртывания на **выделенном сервере**. Он не трогает
BigBlueButton и не подключается к `post_publish` — вместо этого вы вручную (или
по API) добавляете ссылку на запись вида

```
https://<host>/playback/presentation/2.3/<meeting-id>
```

и панель сама ставит её в очередь, запускает конвертацию существующим
движком (Chrome в Xvfb + ffmpeg, тот же `bbb-mp4.js`/`ffmpeg-cmd.sh`, что и в
исходном проекте — **логика захвата не менялась**), показывает статус и
прогресс, пишет подробные логи, умеет перезапускать упавшие задачи и
присылает email-уведомления.

## Возможности

- Очередь с ограничением числа одновременных конвертаций (чтобы не положить
  сервер, если закинуть сразу много ссылок).
- Статусы в реальном времени (через SSE, без перезагрузки страницы):
  `В очереди → Выполняется (этап + % прогресса) → Готово / Ошибка`.
- Подробный лог на каждую задачу (консоль Chrome/Puppeteer + вывод ffmpeg),
  просмотр в браузере и скачивание файла лога.
- Кнопки: поставить в очередь, отменить, повторить/перезапустить, удалить.
- Скачивание готового mp4 прямо из панели.
- Email-уведомления об успехе/ошибке через внешний SMTP.
- Простая авторизация (логин/пароль), т.к. сервис может быть доступен из сети.
- Хранение состояния в SQLite — переживает перезапуск сервиса (незавершённые
  задачи помечаются ошибкой с понятным сообщением, задачи в очереди
  перезапускаются автоматически).

## Два режима запуска конвертации (`WORKER_MODE`)

- **`docker` (по умолчанию)** — для каждой задачи поднимается контейнер из
  образа `bbb-mp4-worker` (собирается из `Dockerfile` в корне репозитория —
  это тот же образ, что использовался в исходной интеграции с BBB).
  Изоляция, легко ограничить ресурсы (`DOCKER_CPUS`, `DOCKER_MEMORY`).
- **`local`** — панель запускает `node bbb-mp4.js <url>` прямо на хосте, без
  Docker. Требует установленных на сервере Chrome, ffmpeg, Xvfb, Pulseaudio
  и `npm install`, выполненного в корне репозитория (см. список пакетов в
  корневом `Dockerfile`/`dependencies_check.sh`). Проще в деплое, но без
  изоляции между задачами.

## Быстрый старт (Docker, рекомендуется)

```sh
# На новом сервере
git clone https://github.com/vsesem-git/bbb-mp4-for-bbb2.7.X.git
cd bbb-mp4-for-bbb2.7.X

# 1. Настройте панель
cp webapp/.env.example webapp/.env
nano webapp/.env   # ADMIN_USERNAME/ADMIN_PASSWORD, SMTP_*, MAX_CONCURRENT_JOBS...

# 2. Соберите образ-воркер (тот же движок захвата, что и раньше)
docker build -t bbb-mp4-worker .

# 3. Поднимите панель (собирается из webapp/Dockerfile)
export HOST_DATA_DIR=/opt/bbb-mp4/data      # абсолютный путь на ЭТОМ сервере
export HOST_OUTPUT_DIR=$HOST_DATA_DIR/output
mkdir -p "$HOST_OUTPUT_DIR"
docker compose up -d --build

# 4. Откройте http://<сервер>:8080 и войдите с ADMIN_USERNAME/ADMIN_PASSWORD
```

> Важно про `HOST_OUTPUT_DIR`: панель сама работает в контейнере и общается с
> Docker-демоном хоста через смонтированный `/var/run/docker.sock`
> (docker-outside-of-docker). Поэтому когда она просит хост запустить
> контейнер-воркер с `-v <путь>:/usr/src/app/processed`, этот `<путь>` обязан
> быть путём **на хосте**, а не путём внутри контейнера панели — отсюда и
> отдельная переменная `HOST_OUTPUT_DIR` (должна совпадать с тем, что
> смонтировано в `docker-compose.yml` как `HOST_DATA_DIR/output`).

## Запуск без Docker (режим `local`)

```sh
cd bbb-mp4-for-bbb2.7.X
npm install                 # puppeteer + xvfb для самого движка захвата
./dependencies_check.sh     # доустановит системные библиотеки для Chrome
# Установите также: google-chrome-stable, ffmpeg, xvfb, pulseaudio (см. Dockerfile)

cd webapp
npm install
cp .env.example .env
# В .env укажите WORKER_MODE=local
node server.js              # или через pm2/systemd для продакшена
```

## Переменные окружения

См. `webapp/.env.example` — там каждая переменная с комментарием
(авторизация, пути хранения, лимит параллелизма, список разрешённых хостов
для ссылок, SMTP).

## Безопасность

- Панель закрыта логином/паролем (`ADMIN_USERNAME`/`ADMIN_PASSWORD` или
  `ADMIN_PASSWORD_HASH` — bcrypt-хэш, предпочтительнее для прода).
- Если сервис смотрит в интернет — обязательно поставьте `ALLOWED_HOSTS`
  (список доменов, с которых разрешено принимать ссылки на запись), иначе
  авторизованный пользователь панели сможет заставить сервер обратиться на
  произвольный URL.
- Рекомендуется держать панель за HTTPS-реверс-прокси (nginx/traefik) и/или
  ограничить доступ по IP/VPN.

## Как это устроено внутри

- `server.js` — Express-приложение, отдаёт API и статику.
- `src/queue.js` — очередь в памяти процесса с ограничением параллелизма,
  восстанавливается из SQLite при старте.
- `src/worker.js` — запускает `docker run` (или `node bbb-mp4.js` в local
  режиме), построчно парсит вывод (специальные метки `STAGE:`, `DURATION:`,
  прогресс ffmpeg через `-progress pipe:1`) и обновляет статус задачи.
- `src/db.js` — SQLite через встроенный в Node `node:sqlite` (без native
  зависимостей, Node ≥ 22.5).
- `src/mailer.js` — email-уведомления через nodemailer.
- `public/` + `views/app.html` — фронтенд на чистом JS (без сборки), живые
  обновления через Server-Sent Events (`/api/stream`).
